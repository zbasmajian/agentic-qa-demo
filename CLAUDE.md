# Project instructions for Claude

## Test healing policy

Follow this whenever you fix, heal or debug failing tests, including when you run as the `playwright-test-healer` agent. Source: `docs/healing-policy.md`.

The healer (the `playwright-test-healer` agent, or Claude fixing failing tests) may change only test code under `tests/` (spec files, page objects and fixtures). It may do so only when the **test** is out of date and the app is still working correctly. Examples: updating a locator after an intentional UI or accessible-name change it has confirmed in a live page snapshot, fixing timing or synchronization, or refreshing test data. It must never edit application code (`src/`), `playwright.config.ts`, or the plans in `specs/`. It must never make a test pass by deleting or loosening assertions, changing expected values to match new behavior, adding `test.fixme()`/`test.skip()`, or switching to brittle CSS or XPath selectors. When a failure points to a real application bug, a human decides what happens next: stop, change nothing, and report the root cause with evidence (file and line, error, HTTP status) plus a suggested app fix. Application bugs include a 5xx response, a runtime error such as `ReferenceError`, a crash or blank page, or behavior that contradicts the spec. The same goes for an accessible name or text change that might not be intentional, like `Task Input` → `Task2 Input`, and for any fix that would change more than a few locators.
